# 添加数字行表格规范

> 来源：CNAP Figma 文件 `GRkvwNuoeXDYxS7yJ3Bpru`
> 参考节点：`546:14742`
> 提取范围：可重复添加的数字输入行表格模式
> 文档用途：供后续页面实现、组件抽取和视觉走查复用。
> 证据限制：当前节点是规范示例，不包含完整组件 Variant 定义；未出现的错误提示、加载态和服务端校验不在本规范内。

## 1. 适用场景

用于录入一组结构相同、数量可变的数字配置，例如端口号、实例数量、权重、优先级或资源数值。每一行代表一条独立配置，用户可以增加或删除行。

不得把这个模式用于字段结构不一致的复杂表单；复杂表单应使用分组表单布局。

## 2. 组件结构

组件从上到下固定为：

1. 表格标题或字段说明（可选）。
2. 列标题行。
3. 一个或多个数据行。
4. “添加一行”操作。

每个数据行包含：

- 一个或多个文本/数字输入框。
- 一个行级删除按钮。
- 数字字段必须使用 `inputmode="numeric"`，并在提交前做数字校验。

推荐 DOM 结构：

```html
<section class="numeric-row-table">
  <div class="numeric-row-table__head" role="row">
    <span>字段名</span>
    <span>数字值</span>
    <span>操作</span>
  </div>
  <div class="numeric-row-table__row" role="row">
    <input aria-label="数字值" inputmode="numeric">
    <button type="button" aria-label="删除此行">删除</button>
  </div>
  <button class="numeric-row-table__add" type="button">+ 添加一行</button>
</section>
```

## 3. 尺寸与视觉

| 属性 | 规格 |
|---|---|
| 数据行高度 | 固定 `48px` |
| 输入框高度 | 固定 `32px` |
| 输入框圆角 | `8px` |
| 输入框左右内边距 | `10px` 至 `12px` |
| 列间距 | `16px` 至 `20px`，按容器宽度调整 |
| 数据行分割线 | `1px solid #E8E8E8` |
| 添加按钮高度 | `32px` |
| 添加按钮圆角 | 胶囊形，`16px` 或更大 |
| 数据行背景 | 默认白色；分组卡片内可使用 `#F7F7F7` 容器背景 |
| 辅助文字 | `12px/20px`，使用 `#8F8F8F` |
| 普通正文 | `14px/22px`，使用 `#181818` 或 `#545454` |

宽度必须由容器自适应，列使用稳定的 Grid 轨道。最后一列为操作列，不得因为输入内容变长而被挤出容器。

示例 CSS：

```css
.numeric-row-table__row,
.numeric-row-table__head {
  display: grid;
  grid-template-columns: minmax(0, 1fr) minmax(0, 1fr) 56px;
  min-height: 48px;
  align-items: center;
}

.numeric-row-table__row {
  border-bottom: 1px solid #e8e8e8;
}

.numeric-row-table input {
  width: 100%;
  height: 32px;
  box-sizing: border-box;
  border: 1px solid #d9d9d9;
  border-radius: 8px;
  padding: 4px 10px;
}
```

## 4. 交互规则

- 初始至少保留一行；首次进入时展示设计稿规定的默认行数。
- 每次点击“添加一行”只能新增一行，不得一次性新增多行。
- 新增行插入在现有行末尾，并获得唯一的 `aria-label` 和数据索引。
- 删除按钮只删除当前行，不得改变其它行的输入值。
- 当只剩一行时，删除按钮必须禁用或保留一行，不得让表格变成无行状态；具体取决于业务是否允许空值。
- 输入框允许编辑，数字字段提交时必须校验为合法数字；空值和非法数字应保留在当前行并显示错误状态，不得静默转换成 `0`。
- 操作按钮必须有可访问名称，不能只依赖图标或字符形状。
- 内容超出弹窗/抽屉高度时，滚动应发生在内容区域，表头和底部操作区不能被内容覆盖。

## 5. 状态

本节点明确支持的状态：

- 默认行。
- 可添加行。
- 可删除行。

以下状态未在节点中明确展示，后续实现需要单独补充设计证据：

- 数字非法输入。
- 输入框聚焦、错误和禁用。
- 加载中或保存失败。
- 空表格。

## 6. Agent 实现契约

推荐接口：

```ts
type NumericRow = {
  id: string;
  values: Record<string, string>;
};

type NumericRowTableProps = {
  columns: Array<{
    key: string;
    label: string;
    inputMode?: 'text' | 'numeric';
  }>;
  rows: NumericRow[];
  minRows?: number;
  onAddRow: () => void;
  onDeleteRow: (id: string) => void;
  onChange: (id: string, key: string, value: string) => void;
};
```

实现时必须满足：

- `columns` 的顺序同时决定表头和每行输入顺序。
- 每个数据行使用稳定的 `id`，不得使用数组下标作为删除依据。
- `minRows` 默认值为 `1`；当行数等于 `minRows` 时禁用删除或拒绝删除。
- 操作列始终是独立的固定列，不能参与数字列的自适应压缩。
- 添加和删除后必须保持列轨道、行高和分割线不变。

## 7. Do / Don't

### Do

- 使用统一的 32px 输入框和 48px 数据行。
- 给数字输入设置 `inputmode="numeric"`，同时保留字符串值以支持用户编辑过程。
- 对动态行使用稳定 ID。
- 把新增/删除交互放在表格底部和每行末尾，位置固定。

### Don't

- 不得让每个数据行使用独立的列宽定义。
- 不得通过 `display: contents` 让数据行失去自身 Grid 布局。
- 不得因为新增操作按钮而让输入框出现省略号或被挤出容器。
- 不得一次点击批量生成多个条件行。
- 不得删除最后一行后留下空白的不可操作表格，除非业务明确允许空表格。

## 8. 与当前 Demo 的复用映射

当前工作负载 Demo 中可复用本规范的区域：

- 运行配置的亲和性条件表达式行。
- 新增流量接入第三步的端口映射行。
- 后续涉及端口、实例数量或资源数值的动态配置表。

这些区域必须共享“固定列轨道 + 48px 行高 + 32px 输入框 + 一次添加一行”的行为约束，但可根据 Figma 节点替换列名、颜色和字段数量。

## 9. 基础表格组件基线

> 来源：CNAP Figma 文件 `GRkvwNuoeXDYxS7yJ3Bpru`
> 参考节点：`546:15632`

`546:15632` 是基础 `Table 表格` 组件规范。后续动态表格都应先遵循这套基线，再叠加输入和操作交互。

### 行高

- 表头：`48px`。
- 普通单行单元格：`48px`。
- 双行内容单元格：`72px` 或 `88px`，由内容层级决定，不通过压缩字号解决溢出。
- 同一张表中，同一类数据行必须保持统一行高；表头不能因为内容变长而增高。

### 列轨道

基础表格示例展示了多种固定列组合，包括：

- `40px` 序号列 + `280px` 主内容列 + `146px` 的辅助列。
- `264px + 264px + 264px + 100px` 的四列布局，最后一列为操作列。
- 复杂表格使用 `40px` 固定序号列、多个 `146px` 或 `86px` 辅助列，以及独立的 `100px` 至 `188px` 操作/描述列。

实现原则：

- 使用 `grid-template-columns` 明确列轨道，不能依赖单元格内容自然撑开。
- 操作列必须是独立的固定列，放在最右侧。
- 输入列使用 `minmax(0, 1fr)`，避免长文本把其它列推出容器。
- 表头和数据行必须使用完全相同的列定义。

### 单元格内容

- 表头与普通单元格使用统一的左右内边距，内容从同一条垂直基线开始。
- 多行内容使用上下居中，主信息和辅助信息按层级排列。
- 删除、编辑、更多等操作放在操作列内，不能通过负 margin 覆盖相邻单元格。
- 单元格边界、分割线和背景属于表格层，不应由输入框自行模拟整行结构。

### 条件组映射

条件组表格使用基础表格组件的同一规则：

- 表头和表达式行都保持 `48px`。
- 列顺序固定为 `标签键 / 操作符 / 值 / 操作`。
- 操作列使用独立固定列，不参与前三列的自适应分配。
- 条件组卡片只是分组容器，不能改变表格内部的列基线。
- 点击“添加表达式”只新增一行；点击“添加条件组”只新增一个条件组。
